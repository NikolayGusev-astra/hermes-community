## Безопасность

| Параметр | Значение |
|---|---|
| Secret scanning | включён |
| Push protection | включена (секрет не даст запушить) |
| Dependabot security updates | включены |

Push protection дублирует гейт на стороне GitHub: даже если автор обойдёт локальную
проверку, известный формат токена GitHub не примет.

## Защита ветки `main`

| Параметр | Значение |
|---|---|
| Обязательный PR | да |
| Требуемые проверки | `gate`, strict (ветка должна быть свежей) |
| Ревью | 1 одобрение |
| CODEOWNERS-ревью | обязательно |
| Устаревшие одобрения сбрасываются | да |
| Одобрение последнего пуша | требуется |
| Linear history | да |
| Force push | запрещён |
| Удаление ветки | запрещено |
| Обязательное разрешение обсуждений | да |
| Админ обходит защиту | **да** |

### Почему админ обходит защиту

Единственный мейнтейнер не может одобрить собственный PR: GitHub запрещает
self-approve. С `enforce_admins: true` репозиторий встал бы насмерть на первой же
правке правил. Поэтому владелец может пушить в `main` напрямую, а все остальные —
только через PR с зелёным гейтом и одобрением.

Риск назван честно: владелец способен обойти и гейт, и ревью. Компенсация —
workflow `gate` запускается и на push в `main`, поэтому обход всё равно оставляет
красную проверку в истории. Если появится второй мейнтейнер, флаг включается:

```bash
gh api -X PUT repos/<owner>/hermes-community/branches/main/protection \
  -F enforce_admins=true
```

## Проверки

Workflow `gate` (`.github/workflows/gate.yml`):

- запускается на PR при изменениях в `bundles/`, `tools/`, `schema/`, самом workflow;
- на push в `main` — те же пути, чтобы обход не остался незамеченным;
- ставит `gitleaks`, клонирует `NousResearch/hermes-agent` ради `skills_guard`;
- гоняет `tools/gate.py --changed`, затем по всем наборам.

Контекст проверки для branch protection — `gate` (имя job).

## Что проверить при переезде или передаче репозитория

1. `gate` в списке required checks существует и зеленеет на пустом PR.
2. CODEOWNERS ссылается на существующий аккаунт с правом записи.
3. Push protection включена: `gh api repos/<owner>/hermes-community --jq .security_and_analysis`.
4. Squash включён, merge-commit выключен: иначе история перестанет быть линейной
   и правило linear history заблокирует merge.
