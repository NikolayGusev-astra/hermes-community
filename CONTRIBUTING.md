# Вклад в hermes-community

Спасибо, что делишься. Здесь описан весь путь: от того, что лежит у тебя в
`~/.hermes`, до карточки на сайте.

## Что такое bundle

Один каталог, в котором лежит набор целиком:

```
bundles/<name>/
  manifest.yaml        # обязателен: паспорт набора
  soul.md              # персона и тон
  AGENT.md             # инструкции агенту
  skills/<skill>/SKILL.md
  profiles/<name>.yaml
```

Единица вклада — bundle, а не отдельный скилл. Скилл без персоны ревьюить
нечего, персона без скиллов ничего не делает.

**Почему вместе:** `soul.md` задаёт поведение всегда, скилл — только когда
загружен. Проверять их надо в связке, иначе инъекция в soul проходит мимо
внимания, потому что «это же просто стиль».

## Быстрый путь

Скажи своему агенту: «хочу поделиться набором в hermes-community». Скилл
`packager/` проведёт интервью, соберёт файлы, прогонит гейт и подготовит PR.

Дальше — только ответы на вопросы. Скилл спросит про назначение, лицензию и
риск-класс, а не заставит читать эту инструкцию целиком.

## Путь руками

```bash
git clone https://github.com/<owner>/hermes-community.git
cd hermes-community
git switch -c bundle/my-bundle
cp -r bundles/_template bundles/my-bundle
```

Отредактируй `manifest.yaml` и содержимое, затем:

```bash
python tools/gate.py bundles/my-bundle
```

`OK` — можно пушить. `FAIL` — гейт напечатает правило и строку.

```bash
git add bundles/my-bundle
git commit -m "bundle(my-bundle): краткое назначение"
git push -u origin bundle/my-bundle
gh pr create
```

## Манифест

Полное описание полей — `docs/manifest.md`. Минимум:

```yaml
schema: hermes-bundle/1
name: my-bundle          # a-z, 0-9, дефис; совпадает с каталогом
title: Человеческое название
summary: Одно предложение с результатом.
license: MIT
authors:
  - name: Имя
    github: login
risk:
  network: false
  credentials: false
  money: false
  filesystem: false
  shell: false
entry:
  soul: soul.md
  skills: [skills/my-skill]
```

## Риск-класс: не занижай

Пять флагов говорят читателю, что набор трогает. Гейт сверяет их с содержимым:
`requests.get` в тексте при `network: false` — FAIL. Завышать можно, занижать
нельзя.

| Флаг | Значит |
|---|---|
| `network` | ходит в интернет |
| `credentials` | нужны ключи, токены, пароли |
| `money` | трогает деньги, сделки, заказы |
| `filesystem` | пишет вне своего каталога |
| `shell` | запускает команды оболочки |

Наборы с `money: true` публикуются только карточкой: код читают отдельно.

## Чего не принимаем

- секреты в любом виде, даже как «пример»;
- чужие скиллы без лицензии, разрешающей раздачу;
- обфускацию: base64, hex-строки, склейку ради сокрытия;
- невидимые символы и инструкции в HTML-комментариях;
- наборы, которые при запуске тянут код из сети: `network: true` обязателен,
  и ревьюер это увидит.

## Что дальше

1. CI прогоняет гейт. Красный — PR не мержится.
2. Человек читает `soul.md` целиком и скиллы. Отвечает в PR.
3. Merge в `main`, тег `bundle/<name>/v1.0.0`.
4. Карточка появляется на сайте, код остаётся в git.

Правки после публикации — новый PR и новый тег. Опубликованное не правят на
месте: иначе проверили одно, а у людей другое.
